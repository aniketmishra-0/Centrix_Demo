Executive Frequently Asked Questions

Q1: Will Centrix slow down classroom PCs during live teaching?

No. Centrix runs as an idle background service consuming < 1% CPU and under 60 MB RAM. It does not perform CPU-intensive video encoding; it only performs file system event listening and asynchronous chunked network upload.

Q2: What happens if a teacher conducts overtime or lectures run 30 minutes late?

Centrix features an adaptive heuristic matching engine. It continuously measures duration overlap against center schedule boundaries. Extended sessions are algorithmically detected and matched with the correct ongoing batch instead of misclassifying into the next slot.

Q3: How does the system behave during complete internet or network outages?

Centrix is engineered offline-first with an embedded SQLite transactional database. All captured lecture metadata and video cuts remain safely queued on the local hard drive. The moment network connectivity is restored, the service automatically resumes uploading without human intervention.

Q4: How are Google Drive credentials and API tokens protected?

Zero credentials or secrets are packaged into the installer executable. OAuth tokens are collected during initial center setup and stored using Windows Data Protection API (DPAPI) machine encryption, preventing unauthorized extraction.
